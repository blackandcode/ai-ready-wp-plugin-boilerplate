# AI-Ready Boilerplate Integration

## Expected paths

The boilerplate currently organizes REST controllers under backend apps, for example:

```text
src/backend/Apps/<App>/Rest/*Controller.php
```

The generated reference belongs at:

```text
docs/api/openapi.yaml
```

Recommended generator infrastructure:

```text
src/framework/Rest/OpenApi/
  OpenApiGenerator.php
  WordPressRouteInspector.php
  WordPressSchemaConverter.php
  OpenApiDocumentFactory.php
  OpenApiMetadataValidator.php

src/backend/Cli/OpenApiCliCommand.php
```

Keep WordPress introspection and OpenAPI conversion outside domain/application services. They are framework/infrastructure concerns.

## CLI

Preferred UX:

```bash
wp ai-ready openapi generate
wp ai-ready openapi check
```

`generate`:

- boots registered plugin REST routes;
- generates OpenAPI 3.1;
- writes `docs/api/openapi.yaml` atomically;
- reports route/operation/component counts.

`check`:

- generates in memory/temp storage;
- compares against tracked `docs/api/openapi.yaml`;
- exits non-zero when stale;
- never modifies the tracked file.

Optional flags may include `--output=<path>` for debugging, but the canonical path remains fixed.

## YAML serialization

For this PHP >=8.3 boilerplate, use a maintained YAML serializer rather than a hand-written emitter. A suitable development dependency is Symfony YAML constrained to a PHP-compatible major, e.g. `symfony/yaml:^7.4` when the repository still supports PHP 8.3.

Keep YAML serialization behind an adapter so the OpenAPI document factory/generator itself returns a PHP array and can also serve JSON to the admin viewer without requiring YAML parsing.

## OpenAPI linting

Use a modern OpenAPI 3.1-aware linter in the Node development toolchain. Recommended command shape:

```bash
npm run openapi:lint
```

The project may use Redocly CLI with a pinned development dependency and a repository `redocly.yaml` policy file.

Add a drift check to CI so a REST code change cannot merge with stale generated docs.

## Settings API Reference UI

Add an `API Reference` tab to the existing Settings React sidebar, but only expose it when plugin development mode is active.

Server-side source of truth for the gate:

```php
wp_is_development_mode( 'plugin' )
```

Recommended bootstrap flag:

```php
'development' => array(
    'pluginMode' => wp_is_development_mode( 'plugin' ),
),
```

Only include the `API Reference` navigation item when `pluginMode` is true.

For the viewer data, prefer a development-only protected REST endpoint returning the **live generated OpenAPI document as JSON** from `OpenApiGenerator`, for example:

```text
GET /ai-ready-wp/v1/developer/openapi
```

Requirements:

- register only when `wp_is_development_mode( 'plugin' )` is true;
- permission callback requires `manage_options` (or the repository's dedicated developer capability if one exists);
- return the generated document array/JSON, not a filesystem path;
- do not make `docs/api/openapi.yaml` writable through REST;
- do not add a production route that merely returns 404/403: do not register it at all outside plugin development mode.

The Settings viewer may use Scalar's React API Reference component or another locally bundled OpenAPI viewer. Do not load runtime assets from a public CDN for the plugin admin UI.

If viewer bundle weight is material, isolate it as a dedicated build entry and enqueue it only for the development-mode API Reference tab/screen rather than statically increasing every production settings-page bundle.

## Generated file header

Canonical YAML should begin with a comment similar to:

```yaml
# GENERATED FILE - DO NOT EDIT.
# Source: registered WordPress REST routes, schemas, and OpenAPI metadata.
# Regenerate: wp ai-ready openapi generate
```

This is a custom in-tree skill. Add `wp-openapi-spec-writer` to `PROTECTED_IN_TREE_SKILLS` in:

```text
tools/agent-skills/sync-agent-skills.mjs
```

Then ensure it exists in all repository skill mirrors used by the project (`.cursor/skills`, `.agents/skills`, and `.claude/skills` if that directory is materialized rather than symlinked/generated by repository tooling).

Update `docs/developers/agent-skills.md` with its trigger and ownership boundary next to `wp-rest-api`.
